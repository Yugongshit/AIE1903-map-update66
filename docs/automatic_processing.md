# 已完成的自动处理与地图分层（2026-11-08）

旧网站用“暂缓基础图更新 / 差异需要复核”概括了不同问题，让已经观测到的路障也像是在等待人工判断。本次按用户的数据工作流取消这一步：处理有限的已交付数据，保存自动结果；资料不能支持的结论明确记为不可得，不创建人工待办。

O001 的 barrier 类别、实例和观测位置已经记录。M3 的标线可靠性诊断不负责否定这些物体标注。持续时间未知也不再覆盖“当前观测到了占用”这一结果。

基础图仍没有结构修改：这些数据只有一次约 19.85 秒的访问，不能自动证明长期性；标线候选还缺少已核验的修改目标、有效覆盖与对齐等条件。`processing_status=complete` 表示本次输入处理完毕，不代表所有科学问题已经得到答案。记录差异也不代表认定它是真实地图错误。

## 自动处理步骤

1. 核对 nuScenes 数据集、场景、地图版本、坐标和候选身份。逐帧检查几何、候选窗口及精确时间；拒绝把嵌套观测移到其他帧或未来时间。
2. 对占用候选保存原标注类别、实例、物体轮廓和占用记录，产生 `event_recorded`。
3. 对标线候选保存实际观测曲线，产生 `difference_recorded`。最近参考线不自动成为已核验修改对象。
4. 没有可用几何时产生已完成的 `no_usable_observation`，不生成虚构记录。
5. 独立输出存在性、持续时间、结构修改资格和基础图动作。当前交付的持续时间为 `unknown`、基础图动作是 `unchanged`，`manual_review_required=false`。
6. 页面“对比处理结果”读取上述保存的几何；案例导出同时包含自动结果、原 M3 诊断与所选帧几何。

这是对现有交付的自动处理与集成修正，没有训练新模型或声称可靠性准确率提高。历史 M3 的七个 `Insufficient Evidence` 诊断原样保留，但不再用它们生成当前人工任务。受控评估中的历史 `Needs Review` 仍是源实验类别，不是网站要求用户执行的流程。

## 输出契约

`python3 -m map_update integrate-m3 ...` 新增以下三个文件；网站构建在 `assets/decisions/` 下提供同名文件。

| 文件 | 用途 |
| --- | --- |
| `automatic_decisions.json` | 29 个候选的已完成结果、理由、来源与计数 |
| `recorded_event_layer.json` | 按候选及实际帧记录占用几何，供离线接口使用 |
| `observed_difference_layer.json` | 按候选及实际帧记录标线差异，不覆盖参考地图 |

旧 `event_layer.json`、`reliability.json` 和 `maintenance.json` 保留原交付契约，供来源追溯；新的自动结果不通过篡改旧诊断来实现。新层不等于在线障碍物服务，Planning 尚未消费这些新增输出。

缺帧只表示该帧没有记录，不补画旧物体、不推断清除。`last_observed_timestamp_ns` 是末次观测时间；整段离线评分及候选关联的在线可用时刻未提供，不能把这一字段当成在线决策时间。也不设置凭空推定的过期时间来证明障碍消失。

维护引擎另修复了占用事件合并问题：同一车道上的不同 `change_id` 分开保存；针对 A 的恢复记录只能结束 A，不能清除 B。调用方须提供稳定事件 ID，并遵守 `fully_observed` 的事件范围约定，见 [输入契约](input_contract.md)。

## 网站行为与验证

中英文页面显示“占用已记录 / 标线差异已记录”和处理计数，分别解释持续性与结构修改资格。“高证据”筛选依据候选自身的 `HIGH_EVIDENCE` 字段，不再借用仅包含两个标线的旧复核优先级列表；20 个高证据候选包含 O001 等 18 个占用候选。该字段仍是源规则等级，不是准确率。

构建、恢复和浏览器验证命令见 [工作台说明](decision-studio.md)。验证应覆盖实际 29 个候选、缺帧、原数据不变、几何导出、事件独立恢复、中英文页面及 Rerun 联动。最终运行记录单独保存，软件通过不能替代真实准确率评价。
