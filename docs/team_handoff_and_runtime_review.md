## 2. 每个模块应该交什么

### 感知／数据同步负责人：补充可判断、可匹配的观测

已有候选、地图和逐帧几何可以保留，重点补以下内容：

1. **候选与地图对象的匹配结果。** 对每个标线差异，说明候选编号、目标地图对象编号、匹配证据、覆盖到原对象的哪一段，以及变化是位置修改、属性修改、新增、删除，还是暂时无法判断。最近的一条地图线不自动等于同一个物理对象；不能确定时保留未知。
2. **有效观测与缺失的区分。** 提供视野、遮挡、图像质量、投影/对齐核验信息及相应帧/要素编号。保留“充分可见但未检出”和“因遮挡无法判断”，同时保留可见且未变化的对象，供可靠性模块建立正常误差基线。
3. **观测几何与范围。** 现有逐帧折线已接入；若要实际替换地图对象，还需说明完整观测段、点顺序、坐标系、单位和误差。不能用中心点、汇总散点或一小段折线替换整条边界。
4. **地图时间角色与可复现入口。** 说明参考地图究竟是历史图、当前图，还是时间角色未核验；提交依赖版本、可配置输入路径、运行命令和小样例。当前原 `run_all.py` 使用旧目录，已由我们的隔离运行器绕开。

建议交付：`candidate_matches.csv`、`visibility.csv`、`alignment_report.json`、必要的几何文件和运行说明。已有文件能表达同样内容时，无需为了名字重做一套。

验收方式：挑一个标线候选，从原图/观测一路追溯到对象匹配、有效帧、类型与几何；同时给出正常对象和遮挡失败样例。

### 可靠性负责人（成员三）：交实际判定输出与依据

1. **可运行代码、依赖和命令**，以及一小份可完整复现的输入输出。
2. **按对象与时间窗口组织的结果表。** 至少包含地图及版本、访问标识、候选/对象编号、坐标系、起止时间；可靠性结论、有效覆盖率、对齐有效性、有效与支持观测计数，以及判定原因。
3. **四种结论的明确含义。** 未发现显著不匹配、疑似地图变化、需要进一步核验、证据不足。缺数据时返回证据不足，不能把感知分数直接当可靠性。
4. **统计与阈值来源。** 若实现了 proposal 中的正常误差模型，交核实为未变化且可观测的样本、残差定义、拟合参数和开发/测试划分；异常统计量或尾部分数可以附带，但不称为校准概率。贝叶斯概率扩展不是最小交付的前提。

建议交付：`reliability_results.json`或CSV、参数配置、正常样本说明及失败案例。

验收方式：同一个候选与地图维护输入在地图、版本、访问、对象/候选和时间窗口上能唯一对应；正常、遮挡、错位样例得到合理且可解释的结论。目前的 `stage3` 只是感知流水线阶段，不是这份交付。

### 规划负责人：交最小规划器和三组对照结果

1. **静态路线规划器先交付。** 包括车道图构建、已编码的行驶方向/转向约束、起点和目标点设置、障碍物与可行驶区域检查。带速度时间的运动规划是扩展，不必先等它完成。
2. **三种策略在相同输入上的结果。** 仅参考地图、全部候选固定惩罚、依据可靠性调整。三组应使用相同起终点、相同障碍和相同可行性检查。
3. **结构化输出。** 场景、访问、决策时间、采用的地图版本、策略名称、路线的有序坐标、行为、是否可行、拒绝原因、路线长度与运行时间；若有轨迹，另附每个点的时间和速度。
4. **失败与检查结果。** 报告无路可走、越界、与障碍区域重叠等情况。占用分数高或标线缺失不直接等于封路，停车方案也需检查。

建议交付：源码、`planner_results.json`或CSV、配置、鸟瞰图，以及三组可比较的运行记录。

验收方式：同一场景可一键切换三种策略，地图版本和决策时刻一致，失败时给出原因。当前尚未收到这份规划器或路线结果；本次演示不展示虚构的规划路线。你的地图维护模块可以先独立联调，不必等待规划全部完成。

### 数据与评估：小组需要共同补齐

1. **独立复访，或明确标注的时序仿真。** 需要同一路段不同实际经过的访问身份、日志、真实采集时间、空间重叠及观测。41个连续帧、重复目录、重复播放都只算一次访问。若没有真实复访，可先用已知变化时间的合成场景评估规则，单独报告。
2. **独立真值。** 候选判断、车辆行为、时空关联目前的217行模板全部未填。补真值、标注来源/人员、证据引用；不能直接复制预测。历史地图变化与长期性还需额外的参考变化/几何及观察窗口定义，三张现有模板不能直接替代。
3. **负例与数据划分。** 包含未变化、短期占用、遮挡、系统投影偏移等案例；同一场景及其扰动版本留在同一数据划分中，阈值只用开发数据确定。

建议交付：`visits.csv`、实际或仿真观测文件、独立标注表、场景划分清单，以及仿真生成配置（如适用）。

### 你的地图维护模块：已有内容与后续责任

已有可运行的接入、质量门控、跨访问规则、标线写入、临时事件、版本回退和可视化。后续主要是与真实可靠性输出匹配、确认跨访问同一对象、联合核验地图时间角色、用独立数据调整阈值，并统计误更新、更新覆盖、几何误差和延迟。

最先联调的最小包：**一个明确匹配的标线候选 + 对应可靠性窗口 + 地图角色说明 + 一组真实独立访问或明确标注的合成时序**。这一组先跑通，再扩大场景数量。当前三次访问、间隔一小时、跨度24小时等仅是演示默认参数，不是统一的真实长期变化定义。

## 3. 现在运行会遇到什么问题

| 问题 | 已核实的现象或后果 | 处理方式 |
| --- | --- | --- |
| 原交付入口使用旧目录 | 在隔离副本直接运行 `run_all.py`，报找不到 `Nuscnenes已处理/processed/processed/...csv` | 已提供 `scripts/verify_upstream.py`，显式指定本项目的 processed 路径；原源码保持不变 |
| GitHub感知目录没有接入校验清单 | 现有 `inspect-delivery` 需要 `manifest.json`，不能把新目录不经整理直接传给它 | 当前使用已核对的 `external/perception_delivery` 归档；其42个对应文件与新目录完全一致 |
| 原三维回放环境不完整 | 当前环境未安装 Rerun，新GitHub目录中没有 `.rrd`；`.cmd` 是Windows启动脚本 | 本次使用不依赖该软件的单文件网页演示；完整三维回放仍需对应录制文件与匹配版本 |
| 无真实可靠性结果 | 当前真实候选无法通过写入前的质量门槛 | 保留证据不足；补成员三的真实输出，不能用高分替代 |
| 只有一次经过 | 约20秒内持续出现不能证明长期存在 | 真实模式更新数为0；持续性逻辑由明确标记的合成复访展示 |
| 标线修改对象和地图时间角色未确认 | 可能把投影误差或地图表达差异写进地图；规范写入接口会拒绝未核验地图角色 | 核实匹配、完整几何及历史/当前关系；不靠改字段名绕过检查 |
| 汇总分数包含之后的帧 | 直接交给更早时刻的规划会泄漏未来信息 | 回放标为离线；在线联调按决策时刻截断，并要求上游按该时刻重算 |
| 没有独立标注 | 准确率、召回率、误更新效果无法从当前输出得出 | 报告未评估；检查通过只说明软件一致性，不是检测准确率 |
| 原型覆盖范围有限 | 目前自动写入只支持标线；复杂拆分/合并、车道拓扑和并发写入没有完整实现 | 演示聚焦标线与事件层；这些扩展单列，不作为已经完成的功能 |

“运行不报错”和“可以自动写地图”是两个不同的验收条件。证据不足时保持零更新，是当前正确的处理行为；不能为了让演示出现变化而修改真实数据的判断结果。

## 5. 演示怎么讲

打开下载包中的 `演示.html`，使用现代浏览器，无需安装Python或模型。若学校管理的浏览器限制本地网页，可在下载目录用 `python3 -m http.server 8000 --bind 127.0.0.1` 提供本地页面后打开；包中也附有直接可看的录屏。

1. **真实场景回放：** 点击播放或拖动时间条，展示参考地图、观测标线、占用轮廓和车辆位置。强调这是实际资料，但只有一次访问，不能直接证明长期变化。
2. **切换受控模拟：** 说明可靠性字段、访问时间和变化均由样例构造，演示的是程序逻辑。
3. **首次与12小时后：** 证据未达到持续性门槛，标线保持不变。
4. **26小时后：** 三次一致观测满足规则，仅更新一条有明确目标的标线；选择其他案例，看到占用只进入事件层、类型未确认的差异被阻止、对齐异常记录被拒绝。
5. **27小时后：** 充分观测确认恢复，临时占用解除。不能因为缺一帧记录就清除事件。
6. **回退原图：** 标线恢复初始位置，历史版本保留，原变化转为待复核。导出按钮可以保存当前阶段的真实引擎输出。

演示输入经现有Python引擎按时间截断计算，网页展示这些结果；地图更新数量不是在页面中伪造。没有规划器交付，因此没有声称或绘制“已验证规划路线”。
