# 开放路网：独立目的地与边界车流

2026-11-15。本轮属于阶段二交通环境修正；阶段三仍处于观测接口准备。真实同学 Planning、模型训练和人工驾驶尚未接入。

## 为什么以前集中在环内

之前选择8条能返回起点的源闭环，车辆反复跟踪固定路线。增加数量和随机速度不会改变这个限制。导出的341段源车道约8.84公里，但最大的强连通分量只有约2.24公里；大量外围路段通向地图裁剪边界，无法返回原环。

新模式 `route_mode=journeys` 使用283段可用有向源车道，去重约7.58公里，包围框约556×486米。旧8条闭环约1.99公里、216×390米。排除固定源障碍附近不可用车道，并递归移除只通向内部断头的道路；没有猜测缺失道路连接。只有原始 connectivity 明确连向导出范围外的断边才成为进出口，当前16处可用入口、21处出口。不是全城，也不是任意两点都互相可达。

## 车辆怎样自主出行

1. 开场按源车道长度分散放车，每条长道路可容纳多车；平行邻道车身包络间隙至少0.6米，纵向及固定物附近保留3米。离出口至少20米，避免刚出生就离场。安全容量不足拒绝创建。
2. 每车按独立随机流选择可达目的地，随机化道路代价并用 Dijkstra 搜索合法有向连接；最近5个目的地降重复，当前拥挤程度轻度影响目的地权重。150–450米是抽样偏好的行程距离，并非每段实际距离的硬约束。这是背景交通规则，未用真实出行需求校准。
3. 车内目标到达后，从当前位置所在车道选择下一段目的地；物理实体连续行驶。IDM跟车、保守路口预约和已有虚线变道继续工作，开放图有9处满足当前长度条件的有向变道候选；仍是超越后回并，尚未实现全面换道决策。
4. 到达经过验证的地图出口时，车减速至不超过0.7米/秒。找到当前安全入口后，旧实体销毁，新实体以零速入场；没有空位就等待。入口按使用次数分散，车身安全间距至少6米并考虑当前速度。进出流量是仿真假设，不是实测城市需求。
5. 控制槽 `P1` 等可复用，但新车有不同 `actor_instance_id`（例如 `traffic-P1-g2`）及原生实体ID。界面不会在旧车、新车间插值，地图观测器清空该新观察车的旧历史。外部接管车辆和 ego 不自动回收；背景新车沿用槽位驾驶参数，目的地随机流随实体代次重新初始化。

道路选择受方向、连接和可达性约束；当前规则不支持逆行、穿墙或跨越未连接道路。也不保证每一秒每条路都均匀有车。

## 观测与地图边界

所有生成对象明确标注仿真。Planning 当前观测中，其他车的 `vehicle_id` 使用实体实例ID，不能把控制槽当成永不变化的车辆身份。自己的 `own_vehicle.vehicle_id` 保留控制槽，另带 `actor_instance_id`。新车不继承旧车私有观测地图；其他观察者保留其各自历史，并依靠当前观测更新。

Planning 白名单不输出其他车的目的地、路线、边界分配、事件时间表或生成器未来答案。原来的围观/调试状态仍可展示全场真值，正式盲测须隔离这类接口。阶段三可选遮挡/漏检/噪声模型继续使用同帧冻结观测；降质观测的“未看见”不等于确认清障。没有实现同学的动态重规划。源物理地图不因观察地图更新而改写。

## 验收和仍需解决的问题

结果见 [验收记录](../demo/simulation/validation/open-road-journeys.json) 和 [实际分布图](../demo/simulation/validation/open-road-distribution.png)。图中点是原生物理仿真实际位置，虚线框为旧闭环覆盖范围；不把新旧实体连成瞬移轨迹。

验收：96车/16人混合180秒，完成47次行程（41次边界退出/新实体入场、6次内部目的地到达），3次变道完成，0记录碰撞；开场56/96车、结束32/96车位于旧闭环包围框外，结束覆盖23个80米网格，实际访问167段源车道。同一实体每0.1秒最大位移约0.30001米。128车无事件压力60秒，39次行程/37次边界替换、0碰撞，结束60车在旧范围外、31个网格。

**不能据此宣称持续交通已成熟：**96车混合场景到180秒仅10车速度超过0.3米/秒，48车报告路口让行，1车偏离可跟踪车道姿态而安全停止；最后30秒94个未替换实体中68个首尾位移不足1米。128车试验最后仍60车运动，但也有1车姿态不满足跟踪条件。无碰撞验收没有排除堵塞。这些情况已作为下一阶段二修复重点记录。

372项仿真回归、最后8项开放路线专项、11项网页检查通过。云端96车180仿真秒耗时约599秒，128车60秒耗时约293秒；期间有并行测试，不能视为受控性能基准，也不承诺实时。

可复现命令（输出目录必须不存在）：

```bash
python scripts/validate_journey_traffic.py --out outputs/journey-check --cars 96 --seconds 180 --seed 0 --mixed
python scripts/validate_journey_traffic.py --out outputs/journey-pressure --cars 128 --seconds 60 --seed 7
python scripts/check_journey_traffic.py --url http://127.0.0.1:8093 --out outputs/journey-browser
```

短时无碰撞不等于已经证明长期无堵塞、车身始终在车道内或行人交互成熟。高密度排队、路口预约保守、行人路缘停滞仍需处理；当前车辆速度上限3米/秒，尚未校准真实速度和出行分布。原生仿真可能慢于实时。

下一步阶段二重点是长时间吞吐/堵塞定位、路口和换道交互、源数据校准；阶段三做有覆盖证据的地图状态估计及漏检/误检/延迟评估。模型来源和训练思路继续参见 [阶段二/三方案](lane_traffic_and_stage3.md)，未宣称已训练 TrafficGen 或 TrafficBots。之后再接真实 Planning，固定初始物理世界与演化规则，对比不同地图输入；反馈式车辆可能使后续轨迹不同，不能把两次闭环称为完全相同的未来世界。
