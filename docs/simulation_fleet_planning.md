# 把更新地图交给其他车辆 Planning

平台新增 **多车 Planning**：原始采集车 A 继续回放；实验车辆 B、C 各自持有地图、目标、规划器和接收版本，通过转向与油门控制 MetaDrive 物理车辆。道路结构更新改变可行车道和连接关系；障碍、施工等附着状态作为独立的占用信息参与规划与停车判断。

## 启动与入口

已有 `aie1903-sim` 环境时，在 Mac 终端运行：

```bash
cd ~/Desktop/AIE1903-map-update66
git pull --ff-only
conda activate aie1903-sim
python scripts/run_simulation_platform.py
```

浏览器访问 **http://127.0.0.1:8091/**。更新代码后，先在原服务终端按 `Ctrl+C`，再重新启动并强制刷新网页；无需重新安装依赖。端口占用可加 `--port 8092`。完整平台操作见[场景平台说明](simulation_platform.md)。

1. 选择 **nuScenes · scene-0980** 或 **Argoverse · Winter 2021**。
2. 展开道路工具栏下的 **多车 Planning**。
3. 选择交付方式和“车辆知道什么”，点击 **启动多车 Planning**，从第 0 帧开始一次新实验。
4. 播放后查看 B、C 的实际位置、速度、接收版本、重新规划或停车原因。可暂停、调整视角、定位时间点。

默认使用经过源地图和初始占用检查的两个独立目标。也可展开 **设置 B / C 的目标点**，填写源城市坐标的 X、Y 米值，再启动实验。新目标需要位于可访问的源车道附近；没有合法连接时车辆应停车。普通 **启动 MetaDrive** 仍启动原有记录回放。

## 离线对照：同一个物理世界，不同地图认知

选择 **离线先验 · 开场已知**，分别启动以下三组实验。每次重开使用相同的 B/C 初始位置和目标；物理世界始终载入更新后的道路和固定静态障碍。

| “车辆知道什么” | 规划读取的道路图 | 收到的附着状态 | 物理场景 |
| --- | --- | --- | --- |
| 原始地图（`old`） | 原始道路 | 无共享状态 | 更新后的同一场景 |
| 仅更新道路结构（`structure`） | 更新道路 | 无共享状态 | 更新后的同一场景 |
| 道路结构 + 附着状态（`full`） | 更新道路 | 显式给定的全场景先验 | 更新后的同一场景 |

因此，“原始地图”表示车辆还不知道修订，并不会把真实道路或路障一并恢复成旧世界。三组都保留相同的近距离刹车保护；旧地图车辆仍可能因为眼前障碍停车。对照应查看收到更新后的路线、停车位置和原因，不能只比较是否碰撞。

`full` 把整段记录中的状态预先给定，导出会明确标注 `offline_prior: true`。这是“其他车出发前拿到了完整地图包”的实验条件，不能作为在线实时发现变化的证明。

## 在线订阅：区分发布、接收和车辆自己的认知

选择 **在线订阅 · 按观测接收** 后启动。车辆初始使用原始道路认知，状态随原记录的观测时间更新；**发布当前已知更新** 将当前可用更新交给地图服务，并向启用订阅的车辆投递。道路结构来自已经计算并绑定来源的更新产物，这个按钮不重新运行检测算法。附着状态只采用当前帧已经观测到的记录。

B、C 卡片各有 **订阅** 开关。可暂停，在 C 上关闭订阅，再发布更新，观察 B 的接收版本和路线变化、C 保留的旧版本。发布与接收是两个时刻：看到服务已经发布，不代表某辆关闭订阅的车已收到。操作会在当前帧暂停后执行，随后继续播放。

每辆车独立缓存收到的地图与状态，有自己的重新规划次数和原因。车辆的实际运动由物理步进产生；更新消息不会把车辆直接挪到新路线。向后定位会重置场景、重新步进并重放已经记录的发布/订阅操作。

## 两个场景分别验证什么

**nuScenes · scene-0980：附着状态共享。** 当前真实算法输出没有道路结构补丁，因此 `old` 与 `structure` 的道路认知一致。B 的源车道通向真实占用区域，收到阻断状态后应停车；源路网没有相应的可用绕行连接，不能凭空画出一条绕路。B 从 A 及其初始后车的后方合法上游车道出发，避免完整先验使 B 停住后被记录回放车辆追尾。C 使用旁边的独立车道和目标，作为继续行驶的对照。两车起点均检查了第 0 帧交通及固定静态障碍，目标不来自 A 的未来轨迹。

**Argoverse · Winter 2021：道路连接改变。** B 保持同一物理目标，旧地图路线经过 `ls-168084879`、`ls-168085012`；更新后改经真实新增的 `ls-168084910`、`ls-168084875`，再连接到同一目的车道。C 的目标位于未改变的接近车道内。这些道路改动来自已交付参考更新，不能称为本次自动检测准确率。当前 Argoverse 材料没有可用附着状态，所以 `structure` 与 `full` 应一致。

这两个场景各自使用自己的城市地图和时钟，不混接 nuScenes 障碍与 Argoverse 道路。B、C 是新增实验车辆；道路几何和连接没有为实验而伪造。受控 DEMO 没有经过这一组任务验证，不自动套用真实场景的车辆起终点。

## 看清路线和差异

B 使用蓝色，C 使用紫色。虚线表示上一条规划路线，实线表示当前规划路线，粗线表示车辆已经实际行驶的轨迹。接收版本、已知状态数量、重新规划原因及停车原因，帮助区分“收到更新后改变决策”和“看见近处障碍后刹车”。道路与状态变化的原有标注仍保留。

点击车辆卡片的 **跟随 B / C** 可让真实 MetaDrive 相机跟随该车；之后“看车后”“俯视”等视角按钮继续针对这辆车。多车实验开始时默认跟随 B。

原车 A 与普通背景交通继续按记录回放。它们不会因为 B/C 收到新地图而自动重新规划；真正根据共享地图控制的车辆是 B/C。

## 给 Planning 同学的输入

点击车辆卡片的 **导出 B/C 的 Planning 输入**，取得该车在当前已显示引擎帧的输入，包括：

- 本车实际位置、朝向、速度、尺寸与独立目标。
- 该车最后收到的道路图、地图版本和附着状态。
- 发布步、接收步、源观测时间、`offline_prior` 与输入范围标识。
- 本车附近的局部对象，以及对应帧和会话身份。

导出绑定已显示画面的帧身份，不会因为引擎正在准备下一张图而提前导出未来车辆位置。服务最新版本与该车最后收到的版本可能不同；交给规划器的是后者。关闭订阅的 C 不应通过导出接口悄悄获得 B 已收到的新状态。

位置和目标都采用 **源城市 XY 米制坐标**，朝向使用弧度，速度使用米/秒。网页显示原点、MetaDrive 的运行时居中偏移由平台负责转换；接入方不要重复减原点。源观测时间使用纳秒时间戳；仿真步、发布步和接收步分别保留。离线全场景先验与在线截至当前帧的观测数据有明确范围标识，不能混作同一实时输入。

多车运行时，右上角导出按钮导出 B 的输入；车辆卡片可以分别导出 B/C。退出多车、重新启动普通回放后，右上角恢复[场景 Planning 接口](simulation_platform.md#给-planning-同学的输入)。

## 验证与当前边界

场景任务测试使用随仓库交付的真实地图，检查源车道有向连接、初始车辆占用、独立目标、nuScenes 的 B 占用/C 畅通、Argoverse 的真实连接变更。删除连接会明确失败；删除所有未来车辆坐标不会改变 B/C 任务。可运行：

```bash
python -m unittest tests.test_simulation_fleet_scenarios -v
```

2026-11-13 已另外完成六组完整原生物理回放和两组在线订阅/倒带检查，结果见[可复查的验证摘要](../demo/simulation/validation/fleet_planning_report.json)：

| 场景与车辆 | 原始地图 | 道路结构 + 附着状态 |
| --- | --- | --- |
| Argoverse B | 实际行驶 86.941 米，38.9 秒到达 | 改走更新连接，81.612 米，37.2 秒到达 |
| nuScenes B | 20 秒内行驶 56.281 米，尚未到达局部刹车区域 | 第 0 帧收到阻断状态并停车，20 秒内无主动行驶 |
| nuScenes C | 17.1 秒到达 | 17.1 秒到达 |

八次运行中的 B/C 均没有检测到碰撞。nuScenes 的仅结构组与旧图一致，Argoverse 的仅结构组与完整更新一致。在线检查还覆盖了订阅隔离、重新接收、发布后重规划，以及倒带恢复原来的接收版本与物理位置。路径连接检查针对每辆车**实际收到的地图**，不能将旧地图路径通过检查解释为它符合更新世界中的全部通行规则。

复现原生对照（无需浏览器）：

```bash
python scripts/validate_simulation_fleet.py --output outputs/fleet-validation.json
```

网页上的真实引擎、跟随 B/C、逐车导出、订阅及倒带也已通过浏览器检查。已安装 Playwright/Chromium 的开发环境可在平台运行后执行：

```bash
python scripts/check_simulation_fleet_platform.py --url http://127.0.0.1:8091 --out outputs/fleet-browser
```

这些是两个指定场景的工程对照，不是算法检出准确率或总体驾驶安全率。nuScenes 记录只有 20 秒，旧地图 B 在该窗口内尚未进入局部刹车范围，因此不能由本次对照推导避免碰撞的概率。

当前控制器是低速车道图搜索和跟踪基线，遵守源车道连接及通行用途，并用已收到的状态过滤被占用车道；缺少路径时停车。局部刹车保护使用 25 米内的仿真对象几何，尚不是感知模型。它没有完整的信号灯遵从、交互式让行、行人预测或连续自由空间绕障能力。背景交通按记录回放，也不会响应新增车辆；这些约束应保留在 Planning 对照结果中。
