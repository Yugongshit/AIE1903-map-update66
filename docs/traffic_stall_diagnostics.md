# 持续交通停滞诊断

## 后续修复：服务器中断、预约与物理停步

在 f6f7d55 基础上继续排查，未把上一轮“0记录碰撞”视为阶段二完成。本轮发现并处理：

1. **路线终点可中断步进。** 开放路线末端的21个前视点可能全部相同，近场避障调用投影时抛出 `A lane centerline needs two distinct points`。现在使用实际车头方向做近场检查。另一个终点漏洞是剩余中心线短于车头与制动距离时，避障走廊也被截断：补齐实际车头方向上的近场检查到完整制动视距，目标路线本身不变；等待安全入口的边界车辆保持制动，不以0.1米/秒继续向边界外爬行。
2. **中心线拼接折返和投影跳段。** 源连接车道与其后继短车道可能共享末端，直接拼接会先后退再前进。实际复现P56经过3.138米重叠段时投影跳段并误判反向。现在只裁去方向一致、几何重合的重复段，保持源地图和有向连接不变；行程车道边界按拼接后的实际弧长记录。 当路线经过交叉点或贴近自己的另一段时，全局最近点可能落到后面的反向段，车辆被误判为朝向错误。跟踪、行程推进和预约使用上一帧弧长附近的连续投影；出生/新行程从已知源车道进度初始化。真正离路、反向姿态仍制动，诊断包含航向误差和具体失败类型。没有更改实体位姿。
3. **转弯冲突未被完整预约。** 只有拓扑分叉/汇合点不足以覆盖几何交叉的转弯连接。现在补充源中心线交点及有限车宽冲突带：用2.3米宽的车辆通行带和2.5米车长方向余量估算合流前的冲突；中心线在0.25米内接近也检查，避免浮点细缝使真实合流被漏掉。参数为仿真安全近似。普通有向首尾连接不额外生成冲突。交汇点采用凸包加6米缓冲，避免大包围圆吞入无关路段；9米以内的相邻区域合并，以容纳车身、出口间隔与下一停车边界余量，以路线实际进入/离开边界为准。互不相交的通行方向可并行；同一入口/出口方向可在IDM约束下跟行。外部静止车只阻塞相交的通行路线。对多次经过同一XY交点的路线，逐个源折线段计算路口交集，再按实际弧长合并。原先把交点投影到整条路线的“第一次出现”会把两次经过路口之间约600米的道路误判为路口内，导致已离开区域的领车继续让行。驶出区域的车辆不再申请后方路口；车尾净空只用于释放占用，不用于把离场车辆重新判成入口申请者。原判定可让前车在出口外等待后车，形成真实循环。未进入路口的预约须重新核对队列头，避免“后车持预约、前车等后车”的循环；边界新实体不继承旧预约。边界入口若处于冲突区内，须等区域及其预约空闲才创建新车，不能只凭出生间距绕过预约；已有背景车在区域内重选目的地时，及时刷新当前通行路线的预约，避免用上一段路线的旧方向判断兼容性。另检查出口能否容纳车辆：当前停止车身占据驶出空间时，不授予新入场预约，界面显示“路口出口排队”，已在区域内的车辆继续由近场避障与IDM控制驶离。对于已有完整出口的开放路线，还计算到下一路口停车边界、当前前车车尾或路线终点的可用空间（最多前视50米），扣除通往同一出口的已有预约所需车长和2米间隔，防止同一空位被重复承诺。若本次目的地紧靠出口，不能把路线终点误当道路尽头并永久拒绝通行：在实际出口及目的地车身净空都满足时，只允许一个终点通行预约，前车清空后才给下一车。路线止于区域内时不臆造后续路线，仍采用已有占用检查。内部目的地重规划和更长时段仍需继续验证。
4. **低速刹车反弹。** 原生四轮固定最大刹车在低速下会反复改变纵向速度符号。背景车制动改为按质量、物理步长和当前纵向动量限制每轮制动冲量；指令减速度上限4米/秒²，不断言实际物理减速度等于指令。仍由Bullet处理轮胎和碰撞，不写位置或速度。外部Planning动作不走此背景车适配。
5. **行人休眠。** 原生Bullet测试确认：休眠刚体设置速度后仍不移动。行走指令现在先唤醒刚体，保留碰撞；之前持续停住的行人5已在原生混合场景恢复行走、经过多个横道。这个修复不代表人类步态或台阶攀爬模型已经实现。
6. **车人互让。** seed7中P87已占到横道边缘，行人8在其车头旁等待，双方持续互让。行人在等待4秒后，只对当前近乎静止的阻塞车辆尝试1–3米的实际退让，限于源步道/横道可行走区域，整段检查身体净空和其他车辆按当前速度、方向外推的扫掠区；无安全路径则继续等待。原横道入场间隙检查保留。后续发现局部车身避让也会互锁，不能只在等待过街间隙时尝试退让；已补齐局部让行分支。每次退让撤销旧过街许可，到达退让点后须重新检查间隙，避免立即走回车前。实际P89/行人8快照可沿源区域退到 `[366,1118]`（离线几何检查），原生效果另由长测验证。没有瞬移、移车、清障或关碰撞。

7. **暂停状态被旧轮询覆盖。** 控制请求完成后，之前发出的状态轮询可能晚到，把页面短暂改回运行状态。客户端按控制请求代次拒收旧响应；浏览器测试延迟真实轮询响应，在暂停完成后再送达，验证不会恢复旧运行状态。

8. **已驶过的路径仍占着预约。** 原通行走廊始终从区域入口开始，即使车辆已驶过交叉点，仍要等其离开整个大合并区域才允许交叉流通过。现从当前弧长减半车长开始保留走廊；车尾、实际车身及尚未行驶的路径仍保护。专项验证“车尾未清空时仍让行，车尾清空但车仍在大区域内时放行”。额外尝试过10秒请求优先级，但原生吞吐退步，已撤回；不能以单元测试通过证明整体交通更好。

循环等待图同时纳入行人当前等待边，防止漏报“车让人、人让车”。旧版只检测车辆之间的循环，不能把其0组结果解释为没有车人互锁。

停车原因保留最近1秒内的明确制动原因、等待对象和年龄，避免采样恰逢加速帧而把反复让行误报为“物理原因未知”。换实体清空历史，等待目标换实体也不继承旧边。行人增加 `physics_active`。这些信息仍只供围观调试，Planning观测白名单不变。

## 历史：f6f7d55提前制动修复

原规则对路口中心前 `radius + 20m` 内所有未获预约车辆立即施加制动。在相邻路口中，这可能让仍占用前一个路口的车辆为了下一个路口提前停下。新的规则保留提前预约，但只在速度相关停车距离内执行路口制动：区域半径 + 半车长 + 2米余量 + 一秒车程 + 按1.4米/秒²估算的制动距离。

路口实际占用检查、物理碰撞、近距离避障和外部控制边界保留。没有删除对象、移动实体或关闭碰撞；这不是完整交通信号优化，也不保证消除所有相互等待。专项测试覆盖前路口尚未驶出时不被远端预约提前制动，以及接近被占路口时仍须停车。

浏览器检查默认使用 `/usr/bin/chromium`，其他系统通过 `--chromium` 指定。原生检查每30仿真秒保存 `progress.json`，最终保存 `report.json`，包含等待关系、行人状态、实例身份、运动数和物理连续性检查。原脚本的 `passed` 表示碰撞/身份/分布等既有检查通过，不表示长期畅通；必须另看末段运动数、停车时长、循环等待和持续行程吞吐。

所有等待图、全场计数和路口预约均为围观调试信息，不加入 `vehicle_perception` 或 Planning 输入。当前观测仍按原白名单输出，不包含未来路线、事件时刻或全场等待图。不同交通规则的本轮对照用于修复背景交通，不是“只改变地图输入”的阶段五规划实验。
